# escapes.csv · 缺陷逃逸账本字段说明

> 🔧 项目无关骨架版 · 项目专属配置见 PROJECT-PROFILE.md
>
> **当前版本：v1.0（2026-06-11 · patch-012）**
>
> 回答 harness 工程的核心问题：**缺陷被哪一层逮住、本应在哪一层被逮住、检出是否在左移**。每个 patch 的效果从此有分母。

---

## 〇、范围铁律

**只记 `.draft` 封板（A7 通过）之后才暴露的缺陷。**

A7 之前被 Loop/A2/A5 拦下的**不记**——那是流水线正常工作，记了变噪音（拦截过程量在 `loops.csv`）。前流水线存量功能的缺陷可记，`关联run_id` 填 `-`。

## 一、字段表（9 列）

| 序 | 字段名 | 值域 | 说明 |
|---|---|---|---|
| 1 | `escape_id` | `ESC-NNN` | 三位递增，append-only |
| 2 | `登记日期` | `YYYY-MM-DD` | |
| 3 | `关联run_id` | 包名 / `-` | 缺陷所属的已交付包；存量功能 `-` |
| 4 | `缺陷一句话` | 文本 | 业务语言（P027）·禁英文逗号（避免 CSV 引号） |
| 5 | `严重度` | `P0` / `P1` / `P2` | |
| 6 | `发现层` | `Codex施工` / `全量回归` / `dev-verify` / `PM灰度` / `线上` / `其他` | 实际在哪一层暴露 |
| 7 | `应拦截层` | `A1` / `A1.5` / `A2` / `A3` / `A5` / `A6` / `A7` / `Loop-1` / `Loop-2` / `Loop-3` / `不可拦截` | 复盘判定本应谁逮住——**直接指挥下一个 patch 打哪个 agent** |
| 8 | `处置` | 文本 | 关联 `OPT-XXX` hotfix 包 / `patch-XXX` / `DIFF-XXX` / `观察` |
| 9 | `状态` | `开放` / `已闭环` | evaluator 周报必检：开放 > 14 天 🚨 / > 30 天 🆘（同 DIFF 阈值） |

## 二、写入时机（挂既有仪式 · 主对话当场 1 行 echo append）

| Hook | 触发 |
|---|---|
| ① P025 灰度 5 分钟发现缺陷 | CLAUDE.md 关键约束 #6 ③ |
| ② hotfix / followup 包立项 | pre-parallel-check 输出提醒（修的是已 done 包缺陷时） |
| ③ DIFF 登记 | log-diff-entry skill 提醒（DIFF 源于已交付包逃逸时） |
| ④ 紧急 patch 合并 | patch 文档头部"关联 escape_id"行 |

追加后跑 `bash scripts/validate-evals-csv.sh escapes --last`。

## 三、首条登记

骨架无种子行：项目首条逃逸从 `ESC-001` 起编。建议首次灰度/线上逮到缺陷时立刻启用本账本（拦截漏斗基线越早越准）。

---

## 四、派生指标（evaluator 周报「拦截漏斗」节消费）

- **分层拦截漏斗**：本周缺陷按发现层计数 + 应拦截层分布（哪个 agent 漏得最多）
- **灰度命中率** = `发现层=PM灰度 条数 ÷ 本周 .done 包数`（**北极星：应趋向 0** · 以项目首个统计周为基线）
- **分路径逃逸率**：join `runs.csv § 交付路径`——检验"哪类需求可以安全旁路流水线"
- **"全过仍漏"计数**：8 agent 全过 + 回归 100% PASS 仍逃逸的条数（机制盲区信号）
- **开放逃逸预警**：> 14 天 🚨 / > 30 天 🆘
