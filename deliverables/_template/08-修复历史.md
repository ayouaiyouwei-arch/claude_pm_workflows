## 一、段落类型与 ID 规则

| 类型 | ID 前缀 | 起草人 | 用途 |
|---|---|---|---|
| `[ROUND-N]` | 交付轮次 | Codex | 第 N 轮代码交付总结 |
| `[QUESTION-N]` | 问题 | Codex / 测试 | 提问，等 PM 答 |
| `[ANSWER-N]` | 回答 | PM | 回答上方 QUESTION |
| `[BUG-N]` | 缺陷 | 测试 | 测试发现的缺陷 |
| `[FIX-N]` | 修复 | Codex | 针对 BUG-N 的修复 |
| `[CONTRACT-DRIFT-N]` | 契约漂移 | Codex | 后端实际与 04 契约不符 |
| `[BASELINE-DRIFT-N]` | 基线漂移 | Codex | 当前 commit 与 02 基线不符 |
| `[VIOLATION-N]` | 越界 | PM / 评审 | Codex 违反白/黑名单的记录 |
| `[DELAY-N]` | 延期 | PM | 节点超期记录 |
| `[MILESTONE-N]` | 里程碑 | PM | 关键节点达成 |
| `[NOTE-N]` | 备注 | 任意 | 杂项 |

> ID 编号建议：每种类型独立递增（如 `[ROUND-1]` / `[ROUND-2]` / `[BUG-1]` / `[BUG-2]`）。

```markdown
- **附件**：<相对路径，可选>
```
