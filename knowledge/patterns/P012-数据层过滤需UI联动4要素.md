# P012 · 数据层过滤需求必有 UI 联动 4 要素

## 描述

PM 提"按 X 过滤数据"类需求时（如按线路过滤事件 / 按状态过滤订单 / 按角色过滤名单）· A1 § 五 UI 要求**仅描述数据层过滤逻辑**（filteredXxx）· 未追问 UI 层是否需要联动反馈 → 研发**严格按文档实施数据层** · UI 层完全无聚焦提示 → PM 灰度发现 "看不出来切了 / 不知道当前在哪个过滤态" → 100% 文档责任。

**关键认知**：PM 头脑中的"过滤"默认带 UI 反馈（看了就知道在哪个态）· 研发眼中的"过滤"是数据层操作 · 不会主动加 UI 联动。**这是 PM-研发的认知鸿沟** · 必须 A1 prompt 强制追问 4 项。

## 触发场景

A1 § 五 UI 要求写到时 · 任一命中即触发硬约束：

- 需求含 "按 X 过滤" / "按 X 筛选" / "按 X 查看"
- A3 § 六新增 `filteredXxx` / `xxxByYyy` 类 derived state

### 4 要素清单（A1 § 4.7 强制逐项明确 "做 / 不做 + 理由"）

| 要素 | 含义 | 示例 |
|---|---|---|
| **1. 标题反馈** | 过滤后右栏 / 列表标题是否变 | "事件列表" → "1号线 · 事件列表" |
| **2. placeholder 反馈** | 空态文案是否变 | "暂无事件" → "1号线当前无待处理事件" |
| **3. 视觉标识反馈** | 是否需要色点 / 标签 / Badge | 标题左侧 2×2 色点 + 主题色 |
| **4. 聚焦反馈** | 是否自动 fitView / scrollIntoView / focus | 选中后地图聚焦相关区域 |
