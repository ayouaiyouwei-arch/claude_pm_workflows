# P015 · PRD 假设实证驱动

## 描述

PM 写原始 PRD / 一句话需求时 · 常含"假设句"（凭印象写的事实声明 · 不一定与代码一致）：

- "复用 X 已有接口"
- "调用 Y 函数"
- "X 字段已存在"
- "Z 状态等同 W 状态"
- "本期 X 不变"
- "近 N 天 = today-(N-1) ~ today"（具体计算语义）
- "X 直接复用 Y"（数据流假设）

A1 拿到 PM 原始 PRD 后 · **第一步必须**：
1. 提取所有"假设句"
2. 对每个假设句跑 grep 验证
3. 在 § 二现状梳理新增"PRD 假设核验"表（4 列）
4. 任一冲突 → Gate 1 缺口识别**必抓出来**让 PM 拍板

**关键认知**：PM 写 PRD 时是从业务直觉出发 · 不会主动去 grep 代码核实。A1 是 PM 与代码之间的"实证翻译官"· 不能照抄 PM PRD 就开始写需求细化。

## 触发条件
