# P018 · 信息冗余检测

## 描述

UI 类需求中 · PM 描述常含 "列表 + 时间线" / "卡片 + 抽屉" / "主区 + 底部辅助区" 等组合 · 看似两个不同区块 · 实际**底层渲染同份数据**。当 A1 默默把这两个区块都写进需求细化 · 研发默默都实现 → 用户上下扫视看到同样的事件 / 订单 / 数据 → 信息冗余 + 体验割裂。

**关键认知**：UI 区块在 PRD 描述里看起来不一样（"列表"vs"时间线"形式不同），但在代码层面可能都派生自同一数据源。A1 必须显式 grep 数据流验证 · 不能照抄 PM 描述。

## 触发条件

A1 写需求细化时 · PM 描述含以下任一组合 → 必产"数据流冗余核验"表：

- "列表 + 时间线" / "table + timeline" / "list + flow"
- "卡片 + 抽屉" / "card + drawer" / "tile + side panel"
- "概览 + 详情" / "summary + detail"（如同组件同字段集 = 冗余）
- "主区 + 底部辅助区" / "primary + secondary section"
- "多个 Tab 显示同一数据集" / "tabs over same dataset"
