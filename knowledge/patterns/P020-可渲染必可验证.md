# P020 · 可渲染必可验证

## 描述

凡是**画在 canvas / WebGL 上、或任何 DOM 与截图都无法可靠断言**的可视化输出（地图折线/脊线、地图站点、地图聚焦/缩放/拖拽、ECharts/canvas 图表、热力图层、轨迹线等），在流水线里**必须先具备"可断言的身份"，否则任何用例都写不出来 → 缺陷必然漏到灰度/生产才被人肉发现**。

这不是"忘了写用例"，是**"想写也没法写"**——属框架结构性盲区，必须用工程+测试双层兜底，不能靠 agent 自觉。

### 三条铁律

1. **A1 必产"渲染契约表"**（地图/canvas/图表类需求触发）
   每个肉眼可见元素一行：`可见元素 | 数据来源 | 预期行为 | 可断言方式`。`可断言方式` 只允许两类：
   - ✅ **DOM/属性可断言**：元素带 `data-*` 测试钩子（如 `data-overlay-type="polyline"` + `data-point-count` + 序列化坐标 `data-overlay-path`）
   - 🔴 **canvas-only 不可断言** → A1 **必须把"补测试钩子"列为给研发的交付硬要求**（写进 01-需求范围与边界 § 验收硬指标 + 03-PRD片段）：
     > 「画在 canvas 上的 overlay 必须带 `data-overlay-type`/`data-point-count`/`data-overlay-path` 钩子，否则验收方无法验证渲染正确性，本需求不予验收」

2. **A6 必产 `[MAP]` 用例**（不靠截图）
   断言 overlay **存在性 + 数量 + 端点坐标**，走 DOM/属性查询或验收 Mock 适配器记录，**严禁只用截图比对**（canvas 截图随瓦片/时刻/设备像素比漂移，不可靠）。

3. **验收 Mock 适配器必须保留几何**（给研发的工程要求）
   若项目用 mock 适配器做 headless 验收，其 `addPolyline` 等方法**必须保留整条 path / 几何数据 + 打 `data-point-count`**，不能只留首点——否则连 headless 验收也断言不了线条形状。

## 触发条件

需求触及以下任一 · A1/A1.5/A6 必跑：

- 地图 overlay：折线/脊线 / 站点 marker / 实体 marker / 轨迹 / 热力图 / 聚焦 fitView / 缩放拖拽交互
- canvas / WebGL / SVG 动态绘制图表（ECharts、自绘甘特、OD 矩阵等）
- 任何"渲染结果只在像素层、DOM 结构里查不到语义"的可视化

## 强制要求清单

- ❌ 严禁地图/canvas 类需求只靠 `[VR]` 截图比对收口（截图测不到线条是否真画出来）
- ❌ 严禁 A1 渲染契约表里 `可断言方式` 留空 / 写"目测" / 写"看截图"
- ✅ canvas-only 元素 → A1 必把"补 data-* 测试钩子"列为研发交付硬要求
- ✅ A6 每个肉眼可见 overlay 至少 1 条 `[MAP]` 用例（存在 + 数量 + 端点坐标）

- A1 是否识别"这是 canvas-only、DOM 测不到"依赖其对技术栈理解 · 新引入可视化库可能漏判
- 研发可能不接"补测试钩子"要求 → PM 在派活提示词里写成验收硬门槛
