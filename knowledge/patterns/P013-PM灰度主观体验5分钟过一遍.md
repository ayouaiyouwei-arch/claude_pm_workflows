# P013 · PM 灰度主观体验 5 分钟过一遍

## 描述

任何包升 `.done` 后 · 即使 P005 dev-verify 自动化 smoke 通过 + 全量回归 100% PASS + 0 blocker · PM **仍必须亲自在 dev 灰度环境用 5 分钟主观体验过一遍核心场景**。理由：

1. **自动化覆盖 ≠ PM 期望覆盖**：用例描述"P0 P1 P2"等机械维度 · 不覆盖 PM "看了爽不爽 / 体验顺不顺" 的主观维度
2. **PRD / 用例无法穷举主观判断**：如"圆角好不好看" / "切换有没有视觉反馈" / "整页是否被遮挡" · PM 看一眼就知道 · 写文档反而难
3. **PM 灰度实拍能产新 OPT 需求**：实战案例 · 自动化 100% PASS · 但 PM 实拍发现 4 个新问题 · 触发 followup 包 · 这是流水线"自进化"的根本输入

## 触发场景

任一 `.done` 包升级后 **必触发**（与 P005 dev-verify 并列默认动作）：

- /new-feature 第 9 步 retrospect 完成后
- promote-deliverable B-后置 .draft → .done 后
- 手动追认 .done 完成后

## 5 分钟过一遍清单（PM 自检脚本）

```
□ 1. 打开本期触及的主页面（按 99-状态 § 五 触及端列表）· 每端 1 分钟主流程过一遍
□ 2. 切换 2 个常见过滤态 / 模式态 · 看视觉反馈是否符合 PM 期望
□ 3. 小屏（如 1366×768）+ 大屏（如 1920×1080）两个浏览器窗口分别开一次 · 看右栏 / 弹层 / 浮动元素是否截断
□ 4. 触发 1 个边界态（如空数据 / 网络错误 / 无权限）· 看 UI 文案 / 颜色 / 占位是否得体
□ 5. 写"PM 主观体验摘要"（≤ 50 字）到 99-状态 § 五 验收痕迹 · 含 ✅ / ⚠️ / 🚨 三档：
   - ✅ 体验顺畅 · 无新问题
   - ⚠️ 发现轻微问题（写问题描述 + 下次跟踪）· 不开新包
   - 🚨 发现 P0 阻断 · 立即开 followup 修复包
```
