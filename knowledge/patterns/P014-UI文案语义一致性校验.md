# P014 · UI 文案语义一致性校验

## 描述

UI 文案（如"近 7 天" / "Last 7 days" / "本周" / "Top 5" / "最近 24h"）的字面语义与实际计算实现存在**认知偏差**。

**行业事实标准**（UXPatterns.dev / MUI / shadcn / Stripe / Linear · 2025+）：
- **"Last N days" / "近 N 天"** = **rolling window**（`today-(N-1) ~ today` · 含今天）
- **"This week / month / quarter" / "本周/月/季"** = **calendar window**（本自然周期起 ~ 终 · **含未来日期** · 后端通常 reject）

PM 头脑中的"近 7 天" = rolling · 但研发凭直觉可能实现为"本 ISO 周"= calendar。当文档 § 4.3 字段清单只写"startDate/endDate (LocalDate)" 而不写"近 7 天 = rolling-7 必须明确" · 研发凭直觉实现 → BUG。

| P011（视觉规范禁模糊形容词）| 视觉层 | "胶囊" vs `rounded-xl 12px` 措辞冲突 |

## 长期工程层根治方案（推荐 · 不在 prompt LOCKED 内）

prompt 层（L3）是补丁 · 工程层（L1+L2）是根治：

### L1 工程层 · TypeScript discriminated union + readonly const

```ts
type Preset = {
  key: 'rolling-7' | 'rolling-30' | 'rolling-90' | 'calendar-week' | 'calendar-month'
  i18nKey: string
  semantic: 'rolling' | 'calendar' | 'point-in-time' | 'event-based'  // ← 编译期强制声明
  calc: (today: Date) => DateRange
  description: string
}

const PRESETS = [
  { key: 'rolling-7', semantic: 'rolling', calc: (t) => ({ start: addDays(t, -6), end: t }), ... },
  // ...
] as const satisfies readonly Preset[]
```

**好处**：label/impl/semantic 三者编译期强绑定 · PM 改 label 必须同步改 impl 否则编译失败 · P014 类 BUG 在源头不可能写出。

### L2 测试层 · @fast-check/vitest property-based test

```ts
import { fc, test } from '@fast-check/vitest'

test.prop([fc.date({ min: new Date('2020-01-01'), max: new Date('2030-12-31') })])(
  'rolling-7 · 永远返回 today-6 ~ today',
  (today) => {
    vi.setSystemTime(today)
    const { start, end } = PRESETS.find(p => p.key === 'rolling-7')!.calc(today)
    expect(end).toBe(today)
    expect(daysBetween(start, end)).toBe(6)
  }
)
```

单 `fc.property` 跑 11 年 × 365 天 ≈ 4000 边界日 · 取代手写 6 条 [BV-LABEL]。
