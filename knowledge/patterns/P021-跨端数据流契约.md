# P021 · 跨端数据流契约

## 描述

当一个领域数据有**写入端**（某页面/编辑器保存它）和**读取端**（另一个页面/视图展示它），而两端**各画各的、中间没有契约约束**时，会出现"存的是一套、显示的是另一套"的隐性割裂——8 agent 全过、全量回归 100% 仍漏，因为没有任何一道闸去比对"写入端存的"和"读取端读的"是否同一份。

两个高发病灶：

1. **黑盒存储字段**：保存接口用 `payload: unknown` / `data: any` / 一团 JSON blob 装业务数据 → 接口契约核查遇到 `unknown` 直接失明，不知道里面装了什么 → 无类型约束、无序列化用例。
2. **读取端不读写入端存的、自己重建**：编辑端存了一套几何/数据，展示端却不读它、用别的来源重新拼 → 两套数据，永远可能不一致。

## 触发条件

A1/A3 在需求分析阶段命中任一 · 必跑：

- 需求涉及"编辑/保存 X" + 另一处"展示/渲染 X"（同一领域对象的写入端 + 读取端）
- 接口契约里出现 `payload` / `data` / `config` / `extra` 等 `unknown` / `any` / 无结构 JSON 字段
- PM 描述含"编辑器存的会在 XX 页面显示" / "保存后大屏/列表/详情同步"

## 强制要求清单

**A1 跨端数据流契约表**（每个跨端领域对象一行）：

| 领域对象 | 写入端（页面/字段/存储）| 读取端（页面/字段/来源）| 是否同一份 | 一致性判定 |
|---|---|---|---|---|
| 例：某几何路径 | 编辑器 → `payload.path` | 展示端 → 由别的字段重建 | **否（重建）** | 🔴 不一致风险 → Gate 1 必问 PM |

- ❌ "是否同一份" = 否（读取端重建）→ Gate 1 必抓出来问 PM："两端是否应显示完全一致？读取端是否应直接读写入端存的数据？"
- ❌ 接口字段 `unknown` / `any` → A3 严禁原样照抄，必须 grep 写入实参 + 读取解析展开真实结构（展不开标 🔴 转研发暴露 schema）
- ✅ "是否同一份" = 是 → 必产 1 条 round-trip 用例：写入端保存 → 读取端打开 → 断言渲染结果与保存输入一致

## 残余风险

- "重建"有时是有意为之（如读取端要做坐标系转换/投影）· A1 需区分"合理重建"vs"该读没读"，拿不准一律 Gate 1 问 PM
- `payload:unknown` 真实结构可能后端动态拼装、前端无静态类型 → A3 grep 不到时标 🔴 转研发确认
