# 用例字段说明

> 🔧 项目无关骨架版 · 示例均为占位 · 项目专属配置见 PROJECT-PROFILE.md

> 本文件是 `test-cases/<模块>.csv` 与 `templates/用例CSV模板.csv` 的**字段冻结说明**。任何字段调整必须先改本文件并经测试负责人评审，再批量改 CSV。
>
> **场景化是硬性要求**：每条用例必须能写成 `Given/When/Then` 形态，且 `scenario` 字段必须以 `[<方法标签>]` 开头。方法论与标签集合见 `_测试设计方法.md`。

---

## 〇、场景化用例硬性要求（与 `_测试设计方法.md` 联动）

任何进入本目录的用例必须满足：

1. **方法标签**：`scenario` 字段以 `[...]` 开头（来自 6 大方法：`EC` / `BV` / `DT` / `SC` / `EG` / `ST`，可组合，如 `[SC+ST]` / `[BV+EG]`）
2. **可写成 Given/When/Then**：`steps` + `expected` 加起来必须能映射回「前置 → 动作 → 预期」三段；只写「点击按钮 / 校验返回」= 用例无效
3. **优先级配比**：每模块 P0:P1:P2 ≈ 30:50:20（任一档差异 > 20 个百分点即返工）
4. **覆盖率**：5 态 100% 覆盖；状态实体的合法迁移 100% + 关键非法迁移 ≥ 60%；判定表每条规则 ≥ 1 用例；权限多角色矩阵每个角色 ≥ 1 用例

详见 `_测试设计方法.md` § 五、§ 六、§ 七。

## 一、CSV 通用约定

- **编码**：UTF-8 **无 BOM**
- **换行**：LF（即 `\n`，禁止 `\r\n`）
- **分隔符**：英文逗号 `,`
- **引号**：含逗号 `,` 或换行 `\n` 的字段**必须**用双引号 `"` 包裹；字段内部双引号转义为 `""`
- **多值字段**（`fe_ref` / `diff_ref` / `five_states` / `evidence_required` / `steps` / `expected` / `preconditions`）：内部用**英文分号** `;` 分隔；`steps` / `expected` / `preconditions` 内部多行用**字面量** `\n`（即写两个字符 `\` + `n`，工具读取时按行拆分）

## 三、字段中英对照与详解

| 英文字段 | 中文 | 必填 | 含义与示例 |
|---|---|---|---|
| `case_id` | 用例编号 | ✅ | `TC-<模块缩写>-<3 位序号>`，例 `<TC-XXX-001>`（缩写见 § 四） |
| `module` | 模块 | ✅ | 中文模块名，与 `02-页面-产品-代码对照矩阵.md` 一致，例 `<示例模块>` |
| `page` | 页面 | ✅ | 中文页面名，例 `<某监控页>` |
| `route` | 前端路由 | ✅ | 含项目前缀的相对路由，例 `/admin/<模块>/<页面>` |
| `fe_ref` | 关联问题编号 | 视情况 | 来自 `03-页面交互问题清单.md` 的 `FE-XXX`；多值用 `;`，例 `FE-001;FE-007` |
| `diff_ref` | 关联差异编号 | 视情况 | 来自 `baseline/02-PRD-实现差异台账.md` 的 `<DIFF-XXX>`；多值用 `;` |
| `baseline_version` | 用例所属基线 | ✅ | 用例新增 / 修改时所属基线版本，例 `<B1.0.x>` |
| `priority` | 优先级 | ✅ | `P0` / `P1` / `P2`；模块配比 ≈ 30:50:20（详见 `_测试设计方法.md` § 五） |
| `scenario` | 场景描述 | ✅ | **必须**以方法标签 `[...]` 开头 + 句式 `<角色> <动作> <对象>，校验 <核心断言>（<关键预期>）`；≤ 120 字。反例：`测试登录`；正例：`[SC] <角色>登录后查看<某列表>，断网时能给出错误提示与重试入口`。详见 `_测试设计方法.md` § 七 |
| `preconditions` | 前置条件 | ✅ | 多条用 `;` 或 `\n`，例 `已启动后端;<禁用 Mock 的环境变量>=false;<角色>账号已存在` |
| `steps` | 步骤 | ✅ | 格式 `1) ...;2) ...;3) ...` 或 `1) ...\n2) ...\n3) ...`；步骤号必须从 1 起 |
| `expected` | 预期结果 | ✅ | 按步骤号或合并描述；与 `steps` 对齐，例 `1) 跳转 /admin/<首页>;2) N 张卡片有数据;3) 控制台无 error` |
| `five_states` | 五态核查 | ✅ | `loading;empty;error;success;permission`；某条不适用写 `na`（不允许整字段为空） |
| `evidence_required` | 必交证据 | ✅ | `screenshot;network;sql` 三选多；至少 1 项 |
| `automation_type` | 自动化类型 | ✅ | `manual` / `api` / `e2e` / `hybrid` |
| `automation_path` | 自动化路径 | 视情况 | Bruno `.bru` 路径或 Playwright `.spec.ts` 路径，**相对 `test/tools/`**；纯手工写 `na` |
| `owner` | 负责人 | ✅ | 测试 / 维护人姓名或 RoleID |
| `last_updated` | 最近更新日期 | ✅ | `YYYY-MM-DD` |

## 五、`automation_type` 与 `automation_path` 配对

| `automation_type` | `automation_path` 写法 |
|---|---|
| `manual` | 固定写 `na` |
| `api` | Bruno 路径，相对 `test/tools/`，例 `api-collection/<模块>/GET_<资源>.bru` |
| `e2e` | Playwright 路径，相对 `test/tools/`，例 `e2e-scripts/tests/regression/<模块>/<TC-XXX-001>.spec.ts` |
| `hybrid` | 用 `;` 分隔多路径，例 `api-collection/<模块>/GET_<资源>.bru;e2e-scripts/tests/regression/<模块>/<TC-XXX-001>.spec.ts` |

## 六、用例书写要求

1. **场景化（硬要求）**：`scenario` 字段以方法标签开头，能写成 Given/When/Then；详见 `_测试设计方法.md` § 七
2. **一例一目的**：禁止把多个独立校验糅在一条用例里
3. **可重复**：步骤必须可由不熟悉本系统的人按顺序复现
4. **可判定**：预期必须可被「截图 + 网络日志 + SQL」三选其一证伪
5. **可追溯**：`fe_ref` / `diff_ref` 必须真实存在；新增用例同时新增 `FE-XXX` / `DIFF-XXX` 时，本字段不能为空
6. **不写敏感数据**：`preconditions` / `steps` / `expected` 不允许出现真实手机号 / 身份证号 / 生产账号
7. **方法论叠加**：状态实体（任何有显式生命周期的业务实体，如订单 / 工单 / 任务等）至少 1 条 `[ST]`；权限相关至少 1 条 `[DT]`；每模块至少 2 条 `[EG]`

## 七、与执行清单 / 缺陷清单的关系

```
test-cases/<模块>.csv          ← 用例库（事实源）
       │
       │ 调 run-acceptance-suite 技能
       ▼
execution/<版本>/执行清单.csv  ← 跑一次结果就追加一行
       │
       │ result=fail / blocked
       ▼
execution/<版本>/缺陷清单.csv  ← 缺陷登记
       │
       │ 同步登记
       ▼
product-docs/.../baseline/02-PRD-实现差异台账.md
```

> `case_id` 是三张表之间的**主键**：用例库定义、执行清单引用、缺陷清单引用。

## 八、CSV 校验脚本（建议）

> 后续可在 `tools/` 下追加 Python / Node 脚本做静态校验：

- 表头是否冻结
- `case_id` 是否唯一、格式是否合规
- `priority` / `automation_type` / `five_states` 取值是否合规
- `scenario` 字段是否以 `[<方法标签>]` 开头（场景化硬要求）
- `automation_path` 是否真实存在
- `fe_ref` / `diff_ref` 是否在 `03-页面交互问题清单.md` / `baseline/02-PRD-实现差异台账.md` 中存在
- 模块内 P0:P1:P2 配比是否在 30:50:20 ± 20% 范围

校验脚本本身的实现归 M2 阶段，本次先冻结字段语义。
