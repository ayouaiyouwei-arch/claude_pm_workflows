# 测试设计方法（场景化用例的事实源）

> 🔧 项目无关骨架版 · 方法论为骨架价值（保留）· 业务例子均为占位 · 项目专属配置见 PROJECT-PROFILE.md

> 本文件是测试用例**设计方法论的事实源**。所有进入 `test-cases/<模块>.csv` 的用例必须**至少应用 1 种方法**，并在 `scenario` 字段开头用方括号标注（详见 § 七 字段约束）。
>
> **场景化是硬性要求**：每条用例必须能写成 `Given 前置 → When 动作 → Then 预期` 的形态；只写「测试登录」「校验列表」这种动作型描述 = 用例无效。

---

## 〇、闭环驱动（覆盖义务分母 · 生成铁律 · 2026-06-13 新增）

> **用例生成必须"闭环驱动"，不是"加法式"。** 加法式（套 6 方法 + 凑配额、想到哪写到哪）必漏长尾——这是用例"一直不全"的根因。闭环式 = 先列全「覆盖义务清单」（分母）→ 逐条映射用例 → 列未覆盖 → 补到闭环或显式标「有意不测 + 理由」。

### 覆盖义务清单（= 覆盖率分母，生成前**必先枚举**）

| 来源 | 义务（每一条都要有 ≥1 用例或显式豁免） |
|---|---|
| `01-功能说明` | 每个功能点 **FP-xx** |
| `04-业务规则与状态机` | 每条业务规则 R；状态机每条**合法迁移** + 每条**关键非法迁移**；判定表每条规则 R1..Rn；权限矩阵每个「角色 × 操作」格 |
| `03-页面交互问题清单` | 每个 **FE-xxx**（severity 高必覆盖） |
| `baseline/02·03 台账` | 每个关联 **DIFF / CHG**（在途者：现状取证 + 修复后期望，见 § 4.5/4.7） |
| `06-验收测试清单` | 每个验收点 |
| `00-产品全景 § 三` | 每条端到端主流程（**跨模块链路**，见 § 4.4b） |
| （新功能）`01-需求细化` | PRD 每条验收标准 + 本需求触及的上下游模块数据流 |

### 闭环动作（生成收尾，强制）

1. 生成后产**覆盖闭环矩阵**：每条义务 → 对应 case_id 列表 / `未覆盖` / `有意不测（理由）`。
2. **有「未覆盖」= 没生成完**：回去补，直到全闭环或全部显式豁免（不允许沉默漏项）。
3. 闭环矩阵随用例一并产出（落 `reports/<版本>/coverage-matrix.md`），是发布门与 A7/覆盖审计的对照基准。

> 与 § 二 6 方法的关系：**6 方法回答"一条义务怎么测"，闭环驱动回答"别漏义务"**——两者正交、都必须。先闭环列全义务，再对每条义务用合适方法设计。

## 一、为什么要做方法论

| 问题 | 不做方法论 | 做方法论 |
|---|---|---|
| 写啥用例 | 拍脑袋；漏关键场景 | 6 大方法机械覆盖 → 不漏 |
| 优先级 | 重要的没写、不重要的一堆 | 高/中/低按 30/50/20 配比 |
| 是否场景化 | 「点击按钮」「校验返回」 | Given/When/Then 强制场景 |
| 与差异台账 | 用例与 DIFF 不挂钩 | 每条用例必有 `diff_ref` 或显式标注「无现存 DIFF」 |
| 覆盖率 | 不可量化 | 每模块按业务 / 接口 / 五态做矩阵 |

## 二、7 大测试设计方法（必须全部考虑）

| 缩写 | 中文 | 适用 | 在 scenario 字段标签 |
|---|---|---|---|
| **EC** | 等价类划分（Equivalence Class） | 输入字段 / 参数 / 取值范围 | `[EC]` |
| **BV** | 边界值分析（Boundary Value） | 数值边界 / 字符串长度 / 时间窗 | `[BV]` |
| **DT** | 判定表驱动（Decision Table） | 多条件组合 / 权限矩阵 | `[DT]` |
| **SC** | 场景法（Scenario / Use Case） | 用户业务流 / 跨模块链路 | `[SC]` |
| **EG** | 错误猜测（Error Guessing） | 安全 / 并发 / 网络 / 异常 | `[EG]` |
| **ST** | 状态迁移（State Transition） | 工作流状态 / 实体生命周期 | `[ST]` |
| **VR** | 视觉回归（Visual Regression） | UI 重构 / 新增页面 / 视觉改版 | `[VR]` |

> 方法可**组合使用**，例如 `[SC+ST]` = 场景驱动的状态迁移用例；`[BV+EG]` = 边界值附加错误猜测；`[SC+VR]` = 视觉主流程截图比对。

> **特殊标签登记（pattern 驱动 · 与 G1 lint 白名单一致 · 2026-06-14）**：除上述 7 法外，以下由 patterns 触发的标签亦**合法**、可与 7 法组合（如 `[ST+REGRESSION-REVERSE]`）：
> - `[REGRESSION-REVERSE]` 反向回归（P010 · A→B→A 模式，防"改 B 时打翻 A"）
> - `[MAP]` 可渲染必可验证（P020 · 地图/canvas overlay 的存在+数量+几何坐标断言，**严禁用 `[VR]` 截图替代**）
> - `[BV-LABEL]` UI 文案语义边界（P014 · "近 N 天"/"Top N" 等含数字预设按钮的 rolling/calendar/point-in-time 语义校验）
>
> 🔒 G1 lint 方法标签白名单 = 7 法 ∪ 上述特殊标签（`test/tools/lint-cases.js` 的 `ALLOWED_TAGS`）。**新增标签须同步登记此处 + lint 白名单两处**，否则 lint 会判"未登记方法标签"。

> **`[VR]` 触发条件**：本期需求满足以下任一即必须含 `[VR]` 用例：
> - 新增页面 / 整页布局重构
> - 单组件视觉重构（颜色 / 字号 / 间距 / 圆角 / 阴影任一项的"非微调"改动）
> - PM 在视觉规范专家（A1.5）轮次提供了 demo（HTML / 截图 / Figma）
> 不触发条件：纯逻辑改动 / 微视觉修复（< 3 处样式行）。

## 三、应用顺序（推荐）

```
1. SC（场景法）  ← 先理清主流程 / 备选 / 异常 3 类用户流
2. EC（等价类）  ← 把每个输入分类
3. BV（边界值）  ← 在等价类边界上补强
4. DT（判定表）  ← 多条件组合（尤其权限）
5. ST（状态迁移）← 实体生命周期
6. EG（错误猜测）← 经验补漏：null/超大/并发/时区/XSS/SQL注入
7. VR（视觉回归）← 仅 UI 类需求触发；放在最后做截图基线 + token 校验
```

## 四、各方法应用要点（业务例子为占位 · 请替换为本项目领域）

### 4.1 EC · 等价类划分

> **何时用**：注册 / 表单字段 / 接口入参 / 筛选条件

| 步骤 | 动作 |
|---|---|
| 1 | 列出所有输入字段 |
| 2 | 每个字段拆为「合法等价类」+「非法等价类」 |
| 3 | 每类至少 1 条用例 |

**示例（占位）**：某「编码型字段」（如带固定格式的业务编号）

| 类型 | 等价类 | 代表值 | 期望 |
|---|---|---|---|
| 合法 | 标准格式 | `<合法值 A>` | 接受 |
| 合法 | 另一种合法格式 | `<合法值 B>` | 接受 |
| 非法 | 长度不足 | `<过短值>` | 4xx 拒绝 |
| 非法 | 含全角 / 非法字符 | `<含全角值>` | 4xx 拒绝 |
| 非法 | 空 | `''` | 4xx 拒绝 |

> 与 `test/test-data/边界数据.md` § 一 字段长度边界对齐。

### 4.2 BV · 边界值分析

> **Bug 集中在边界**——任何范围都要测 `min-1 / min / min+1 / max-1 / max / max+1`。

**示例（占位）**：`pageSize` 分页（默认 20，上限 200）

| 边界 | 值 | 期望 |
|---|---|---|
| 下界- | -1 | 4xx |
| 下界 | 0 | 4xx（0 无意义） |
| 下界+ | 1 | 接受 |
| 典型 | 20 | 接受 |
| 上界- | 199 | 接受 |
| 上界 | 200 | 接受 |
| 上界+ | 201 | 4xx 上限提示 |

### 4.3 DT · 判定表驱动

> **何时用**：多条件组合行为不同（权限、规则引擎、计费计算）

**示例（占位）**：某「资源关闭」权限矩阵（角色名以本项目 PROJECT-PROFILE.md § 六 为准）

| 规则 | R1 | R2 | R3 | R4 | R5 |
|---|---|---|---|---|---|
| **条件** | | | | | |
| 已登录 | Y | Y | Y | Y | N |
| 角色 = `<管理员角色>` | Y | N | N | N | - |
| 角色 = `<角色A>` | - | Y | N | N | - |
| 角色 = `<角色B>` | - | - | Y | N | - |
| 资源归属本数据域 | - | - | Y | - | - |
| **动作** | | | | | |
| 可关闭资源 | ✓ | ✓ | ✓ | ✗ | ✗ |
| 可处理资源 | ✓ | ✓ | ✓ | ✗ | ✗ |
| 仅可读 | ✗ | ✗ | ✗ | ✓ | ✗ |
| 跳转登录 | ✗ | ✗ | ✗ | ✗ | ✓ |

> R1 ~ R5 每条至少 1 条用例，标 `[DT]`。

### 4.4 SC · 场景法（强制）

> **每条用例**最少都要满足场景法的 Given/When/Then 形态——本项目把 SC 提为**最低要求**（其他方法是「叠加」）。

**示例（占位）**：某角色处理实时上报的记录

```gherkin
Scenario: <角色>处理新记录直至关闭
  Given <角色>已登录
    And 实时通道（如 WebSocket）已建连
    And 记录库无 PENDING 记录
  When 后端 mock 上报 1 条高优记录
  Then 列表 1 秒内自动多出 1 行
    And 记录状态 = PENDING

  When <角色>点击「处理」并填处理人
  Then 记录状态 → HANDLING
    And handled_by 字段写入数据库

  When <角色>点击「关闭」并填关闭原因
  Then 记录状态 → CLOSED
    And closed_at + closed_reason 写入数据库
```

写到 CSV `scenario` 字段时压缩成一句：
> `[SC+ST] <角色>对新上报高优记录执行 处理→关闭 全链路，校验状态机 PENDING→HANDLING→CLOSED 与 SQL 落库`

### 4.4b SC · 跨模块端到端链路（系统级 · 必产 · 2026-06-13 新增）

> **跨模块链路是系统价值所在，也是模块孤立用例的盲区**——多个缺陷恰好长在模块交界（上游写入端→下游读取端的取数回落、跨模块口径/键不一致等）。单模块用例各自为政，没人测「跳与跳之间」。

| 维度 | 要求 |
|---|---|
| 来源 | `00-产品全景 § 三`端到端主流程 + `baseline/02 台账`的**交界 DIFF** + 角色纵切（同一角色全链路作用域一致） |
| case_id | 用 **`SCN`** 前缀（见 `_用例字段说明.md § 四`），落 `test/test-cases/SCN-跨模块场景.csv`（独立套件，不混进单模块 CSV） |
| 配比/形态 | § 三每条主流程 ≥ 1 条 `[SC]`/`[SC+ST]`，串多个模块、**给每一跳的数据传递断言**（不是只验首尾）；P0 偏多属预期（核心链路） |
| 何时产 | 存量：全模块 CASES 闭环后追产一轮；新功能：A6 识别本需求触及的上下游模块 ≥ 2 时，对每条跨界数据流产 round-trip/链路用例 |

> 示例（占位）：`[SC] <角色> 走 <阶段1→阶段2→…→末阶段> 主流程全链，校验同一数据在每一跳正确传递（端到端 <模块A>→<模块B>→…）`

### 4.5 EG · 错误猜测

> **基于经验**——高频错误猜测库（通用，跨项目适用）：

| 类别 | 必测项 |
|---|---|
| Null/空 | null / undefined / 空字符串 / 空数组 / 0 |
| 特殊字符 | `'`（SQL 注入） / `<script>`（XSS） / emoji / Unicode 全角 |
| 并发 | 同 X-Request-Id 重复提交 / 两用户同时改同一资源 / 两人同时关同一记录 |
| 网络 | 接口 500 / 504 / 401 / 403 / WebSocket 断开 |
| 大数据 | 列表 10000 条 / 报表导出 100 万行 / 100MB 文件上传 |
| 类型错乱 | 把 ID 当 number 传（应为 string）/ 枚举大小写 |
| 时间 | 跨日时段 / 时区切换 / 路径穿越 `../` |
| 权限 | `noauth` 直打写接口 / token 过期中途 / 角色被撤销 |
| 状态 | 浏览器后退后重提 / 刷新中途 / 弹窗未关时跳路由 |

> 与 `test/test-data/边界数据.md` § 三 / § 四 / § 五 / § 六 / § 七**严格对齐**。

### 4.6 VR · 视觉回归（Visual Regression）

> **何时用**：UI 重构 / 新增页面 / 视觉改版 — A1.5 视觉规范专家产出 `01.5-视觉规范.md` 或 `attachments/demo/index.html` 的需求必含。

**示例（占位）**：某页 KPI 区视觉重构

| 维度 | 用例要点 | 工具 |
|---|---|---|
| 截图比对（主流程） | 与 `attachments/demo/screenshots/baseline-<page>.png` 相似度 ≥ 98%（参考 `06-验收标准.md § V1`） | Playwright `expect(page).toHaveScreenshot(...)` |
| 截图比对（5 态） | success / loading / empty / error / permission 各 1 张截图与 demo baseline 比对 | 同上 |
| token 一致性 | 实际渲染 hex / 字号 / 圆角 与 `01.5-视觉规范.md` 颜色表 / 字号表 / spacing 表 100% 命中 | 浏览器 DevTools `getComputedStyle` 取值断言 |
| 字号偏差 | 与 demo 标注的 px 字号偏差 = 0（不允许 ±1） | 同上 |
| 间距偏差 | margin / padding / gap 与 demo px 偏差 ≤ 2px | 同上 |
| 响应式断点 | 在 demo 标注的断点宽度（1280 / 1440 等）下截图比对 | Playwright `viewport` |
| 暗色模式（如 demo 含） | 切到 `prefers-color-scheme: dark` 截图比对 | Playwright `colorScheme` |

**示例 scenario 句式（占位）**：
> `[VR+SC] <角色>在<某页>主流程下校验 KPI 区视觉与 demo baseline 截图相似度 ≥ 98%（含 N 张 KPI 卡片间距 / 字号 / 圆角 token 100% 一致）`

**配比要求（仅 UI 类需求）**：

- `[VR]` 用例条数 ≥ 视觉规范涉及页面数 × 3（主流程 + 5 态 + token 校验各 ≥ 1）
- `[VR]` 占总用例比 ≥ 30%（A7 审核硬指标）

**evidence_required 必含**：

- `screenshot`（demo baseline + 实测）
- `network`（DevTools getComputedStyle 抓的 token 值快照，可选）

> A6 起包前必读 `01.5-视觉规范.md` § 颜色表 / 字号表 / spacing 表 / 组件引用表 / demo 路径表，确保用例与视觉规范一一映射。

### 4.7 ST · 状态迁移

> **何时用**：实体有显式生命周期（订单 / 工单 / 任务 / 审批单 等任何有状态机的业务实体）

**示例（占位 · 以订单生命周期为通用教学例）**：

```
[CREATED] --pay--> [PAID] --consume--> [CONSUMED]
                       \
                        --refund--> [REFUNDED]
[CREATED] --cancel--> [CANCELLED]
```

| 当前 | 事件 | 期望新态 | 类型 |
|---|---|---|---|
| CREATED | pay | PAID | 合法 |
| CREATED | cancel | CANCELLED | 合法 |
| PAID | refund | REFUNDED | 合法 |
| PAID | consume | CONSUMED | 合法 |
| CONSUMED | refund | 4xx 拒绝 | 非法 |
| REFUNDED | refund | 4xx 拒绝 | 非法 |
| CANCELLED | pay | 4xx 拒绝 | 非法 |

> 每条合法迁移 ≥ 1 用例 + 关键非法迁移 ≥ 1 用例，标 `[ST]`。

## 五、优先级配比（强制 30/50/20）

| 优先级 | 标准 | 配比 | 触发场景 |
|---|---|---|---|
| **P0** | 核心业务流 / 数据完整性 / 鉴权 / 资金 | ~30% | `<核心闭环>`、`<资金/退款类>`、`<关键资源变更>`、登录 |
| **P1** | 次要业务 / 错误处理 / 边界 / 权限 | ~50% | 列表筛选 / 表单校验 / 状态切换 / 五态非 success |
| **P2** | UI / 不常见组合 / 可用性 | ~20% | UI 微交互 / 提示文案 / 罕见浏览器 |

> 每个模块的用例数若**严重偏离 30/50/20**，`generate-test-case` 技能必须给出告警。

## 六、覆盖率目标（强制）

| 层 | 目标 | 度量 | 备注 |
|---|---|---|---|
| **核心业务接口**（如 auth + 本项目核心业务域，按 PROJECT-PROFILE.md § 四） | ≥ 80% | OpenAPI tag 下的 endpoint 覆盖比 | Bruno 集合按 tag 跑 |
| **其他接口**（CRUD / 报表） | ≥ 70% | 同上 | |
| **5 态**（loading/empty/error/success/permission） | 100% 覆盖（不适用必须显式 `na`） | 每用例 `five_states` 字段统计 | 与铁律 4 一致 |
| **功能点 FP 闭环** | 100%（每个 FP ≥1 用例或显式豁免） | 闭环矩阵 § 九 | 见 § 〇 覆盖义务分母 |
| **跨模块端到端链路（SCN）** | `00 § 三`主流程逐条全覆盖 | `SCN-*.csv` scenario suite | 系统级、模块交界盲区，见 § 4.4b |
| **状态迁移** | 合法迁移 100% + 关键非法迁移 ≥ 60% | ST 类用例数 | |
| **判定表规则** | 每个规则（R1~Rn）≥ 1 用例 | DT 类用例数 | |

## 七、CSV `scenario` 字段句式约束（场景化硬要求）

> 我们**保留 18 列字段冻结**，把方法论标签嵌入 `scenario` 字段第一段。

### 7.1 标准句式

```
[<方法标签集合>] <角色> <动作> <对象>，校验 <核心断言>（<关键预期>）
```

| 段 | 必填 | 例 |
|---|---|---|
| `[<方法标签>]` | ✅ | `[SC+ST]` / `[DT]` / `[BV+EG]` |
| `<角色>` | ✅ | `<管理员 / 某业务角色 / 只读角色 / 普通账号>`（角色见 PROJECT-PROFILE.md § 六） |
| `<动作>` | ✅ | `<处理记录 / 退款 / 变更资源 / 进入编辑模式>` |
| `<对象>` | ✅ | `<某监控页 / 某详情 / 某调整页 / 某编辑器>` |
| `校验 <核心断言>` | ✅ | 状态机正确 / 字段映射一致 / 权限拒绝生效 |
| `（<关键预期>）` | 推荐 | 写出 SQL 落库点或接口契约重点 |

### 7.2 反例 vs 正例

> 左列「反例」是**通用教学反例**（任何项目都不应这样写），保留。右列「正例」用占位角色 / 对象演示标准句式。

| 反例（违规） | 正例 |
|---|---|
| `测试登录` | `[SC] <管理员>账号登录后跳转首页，校验 N 张卡片走单一聚合接口非 Mock` |
| `校验列表筛选` | `[EC+BV] <角色>对<某列表>用 status 筛选 + pageSize 在 1/20/200 边界，校验响应分页字段与列表去重` |
| `换人换车` | `[SC+ST+EG] <角色>对<某资源>执行变更，校验幂等(同 X-Request-Id 重复) + 冲突拒绝(资源被占用) + audit_log 落库` |
| `退款` | `[ST+EG] <管理员>对 PAID 订单退款，校验状态机 PAID→REFUNDED + 同 X-Request-Id 24h 去重 + REFUNDED 不允许再次退款` |

### 7.3 字段长度

- `scenario` ≤ 120 字（CSV 列宽友好）
- 详细 Given/When/Then 写在 `steps` + `expected` 字段（多行用 `\n` 字面量）

## 八、与 `test-cases/<模块>.csv` 的强制约束

| 约束 | 实现 |
|---|---|
| 每条用例至少 1 个方法标签 | `scenario` 字段以 `[...]` 开头 |
| 每模块优先级配比 P0:P1:P2 ≈ 30:50:20 | `generate-test-case` 技能批量生成时校验 |
| 5 态覆盖 100% | `five_states` 字段不允许整字段为空 |
| 状态迁移类实体（任何有显式生命周期的业务实体） | 每实体至少 1 条 `[ST]` 用例覆盖合法迁移 + 1 条非法迁移 |
| 判定表类业务（权限 / 计费 / 规则） | 每个规则行 ≥ 1 用例标 `[DT]` |
| 错误猜测覆盖 | 每模块至少 2 条 `[EG]` 用例（默认含并发 + 异常网络） |

```
| 模块 | EC | BV | DT | SC | EG | ST | 总用例 | P0/P1/P2 |
|------|----|----|----|----|----|----|--------|----------|
| <模块A> | - | - | - | 3 | 1 | - | 4 | 1/2/1 |
| <模块B> | 2 | 2 | 2 | 4 | 3 | 3 | 16 | 5/8/3 |
| ... |
```

> 由 `regression-check` 或 `generate-test-case` 技能输出到 `reports/<版本>/coverage-matrix.md`。

**上表是"方法配比"统计；真正当门禁的是下面的"义务闭环矩阵"（§ 〇 的产物）：**

```
| 义务（来源 FP/R/状态迁移/DT/权限格/FE/DIFF·CHG/链路） | 覆盖 case_id | 状态 |
|---|---|---|
| FP-NN <某功能点> | <TC-XXX-0NN> | ✅ 覆盖 |
| 状态机 <某实体> <某迁移> | <TC-XXX-0NN> | ✅ 覆盖 |
| FP-MM <某功能点> | — | ❌ 未覆盖 → 返工补 |
| 04 §X <某残料分支> | — | ⏸ 有意不测（Q-XXX=A 已裁残料·理由） |
```

> **判定：任一义务为「❌ 未覆盖」= 生成未闭环、不放行。** 配合 `test/tools/lint-cases.js`（G1 静态门禁）+ `coverage-audit` 工作流（独立复核）三层兜底。

## 十一、违规判定

| 行为 | 判定 |
|---|---|
| `scenario` 字段不带 `[...]` 方法标签 | 用例不合规 |
| 仅写「测试 xxx」「校验 xxx」 | 用例不合规 |
| 模块用例配比严重偏离 30/50/20（任一档差异 > 20 个百分点） | 整批用例返工 |
| 5 态字段空 / 缺 `na` | 用例不合规 |
| 状态实体只有 success 路径无 ST 用例 | 整模块用例不合格 |
| 权限类业务无 DT 用例 | 整模块用例不合格 |
| UI 类需求（A1.5 触发）无 `[VR]` 用例或 `[VR]` 占比 < 30% | 整批用例返工 |
| `[VR]` 用例缺 `attachments/demo/screenshots/baseline-*.png` 引用 | 该条用例不合规 |
