# /iterate-A7 · A7 闭环自动迭代

> 用户已输入：$ARGUMENTS

> 🔧 项目无关骨架版 · 项目专属配置见 PROJECT-PROFILE.md

## 适用场景

A7 用例审核打回（结论 = 打回，含 P1 必改项），主对话不想手动重跑"A6 修 → 自检 → A7 重审"，调本命令一次性闭环，**最多 3 轮**自动迭代。

## ⚠️ 触发前提

- `product-docs/_drafts/<短名>/07-A7-用例审核报告.md` 已存在 + 整体结论 = ❌ 打回
- 报告 § 必须修改的问题（P1 阻塞）至少 1 条
- 过去未跑过 `/iterate-A7`，或上次跑完仍未通过且累计轮次 < 3

如不满足，**立即停手**告知用户。

## 第 0 步：定位工作目录

```bash
DRAFT="${ARGUMENTS:-$(cat /tmp/new-feature-current.txt 2>/dev/null)}"
[ -z "$DRAFT" ] && echo "❌ 未指定短名，且 /tmp/new-feature-current.txt 为空" && exit 1
DRAFT_DIR="product-docs/_drafts/$DRAFT"
[ -d "$DRAFT_DIR" ] || { echo "❌ 工作目录不存在: $DRAFT_DIR"; exit 1; }
```

## 第 1 步：读 A7 报告找 P1 项

```bash
A7_REPORT="$DRAFT_DIR/07-A7-用例审核报告.md"
grep -A 50 "## 必须修改的问题\|## 四、必须修改的问题" "$A7_REPORT" | head -80
```

把 P1 必改项原样列给用户**一次**（让用户确认是否要让 A6 自动修）：

> "A7 打回了 N 项 P1：
>  1. <第 1 项>
>  2. <第 2 项>
>  ...
>
> 即将让 A6 按报告修改 06-用例.csv + 06-用例说明.md，然后重新自检 + 调 A7 审。
> 最多 3 轮闭环；3 轮后仍不通过我会停下让你介入。
>
> 是否开始？回复 `开干` 进入第 1 轮。"

等用户回复 `开干` 才进入第 2 步。

## 第 2 步：闭环循环（最多 3 轮）

记录轮次 `N = 1, 2, 3`。每轮做以下 4 件事：

### 2.1 调 A6 按 A7 报告修

```
Task(subagent_type="test-case-author", prompt="
工作目录：product-docs/_drafts/<短名>/
当前是【A7 闭环第 N 轮】（最多 3 轮）。

A7 已打回，必改 P1 项见 07-A7-用例审核报告.md § 必须修改的问题。请：
1. 严格按 A7 报告每条 P1 修改 06-用例.csv 与 06-用例说明.md
2. 不要新增 / 删除用例（除非 A7 报告明确要求），仅修复字段问题
3. 修完跑你 agent 定义的 5 条自检 + UI 类需求时跑 [VR] 占比检查
4. 第 1 句话格式：[A6 闭环修复 第 N 轮] 修复了 K 项 P1，自检 = ✅/❌
")
```

### 2.2 主对话拿到 A6 返回 → 调 A7 重审

```
Task(subagent_type="test-case-reviewer", prompt="
审核对象：product-docs/_drafts/<短名>/06-用例.csv + 06-用例说明.md
当前是【A7 闭环第 N 轮重审】。

请按你 agent 定义跑 Pass1 + Pass2 + Pass3（UI 类多 Pass4），对比上轮报告确认 P1 项已修复。
覆盖原 07-A7-用例审核报告.md，结尾追加 § 闭环第 N 轮 复核结果。
第 1 句话格式：[A7 第 N 轮复核] 整体结论 = 通过/打回，本轮新增问题 = M 个。
")
```

### 2.3 判断退出条件

| A7 第 N 轮结论 | 处置 |
|---|---|
| ✅ 通过 | **退出循环**，告知用户："A7 第 N 轮通过 ✅，可以走 Gate 3 打包"，结束 /iterate-A7 |
| ❌ 打回（同样问题） | 计数 +1；N < 3 → 进第 N+1 轮；N == 3 → 强制停下 |
| ❌ 打回（**新问题**） | 立即停下不进下一轮 — 新问题说明 A6 改坏了，必须 PM 介入 |

### 2.4 第 3 轮失败处置

如 N == 3 仍打回，停下告知用户：

> "❌ A7 闭环跑了 3 轮仍未通过：
>  - 第 1 轮 / 第 2 轮 / 第 3 轮 各打回原因 = ...
>  - 累计未解决 P1：<列表>
>  - **建议处置**：
>    A. 你直接 Edit 06-用例.csv 手动修最后这几项（推荐——AI 救不动了）
>    B. 让 A1 / A3 重新过一遍（如果 A7 反映的是用例与需求不一致，根因在上游）
>    C. 跑 /new-feature 从头来（极少需要）
>
> 我已停下不再自动 loop。"

## 第 3 步：成功收尾

A7 通过后：

```
✅ /iterate-A7 完成
- 工作目录：<DRAFT_DIR>
- 闭环轮数：N（≤ 3）
- 最终 A7 结论：通过
- 06-用例.csv 总条数：<N>
- 07-A7-用例审核报告.md 已更新（含 § 闭环第 N 轮 复核结果）

下一步：回 /new-feature 流水线 Gate 3，进第 8 步打包。
```

## 不允许的事

- ❌ 跑超过 3 轮（计数硬上限）
- ❌ 跳过用户在第 1 步的"开干"确认
- ❌ 让 A6 在闭环里新增 / 删除用例（仅允许修字段；新增 / 删除需走原 /new-feature 第 6 步重做）
- ❌ A7 报告 P1 项还有未读就开干 — 必须先把 P1 项原样列给用户看一眼
- ❌ 同时 loop 多个 _drafts（一次只跑一个）

## 与 /loop 的关系

本命令是"事件驱动 + 上限 3 次"的闭环，**不依赖 /loop 的时间间隔**。如果你确实需要把它包装成自动重试（例如 PM 离开 30 分钟回来要看结果），可以：

```
/loop 60s /iterate-A7 <短名>
```

但通常不必——闭环 3 轮加起来 5-10 分钟就跑完了，主对话同步执行更直接。
