# /iterate-A2 · A2 闭环自动迭代（Loop-2）

> 用户已输入：$ARGUMENTS

## 适用场景

A2 需求审核打回（结论 = ❌ 打回，含 P1 必改项），主对话不想手动重跑"A1 修 → A2 重审"，调本命令一次性闭环，**最多 2 轮**自动迭代（A1 重写成本高于 A6 改字段，上限低于 iterate-A7 的 3 轮）。

## ⚠️ 触发前提

- `product-docs/_drafts/<短名>/02-A2-审核报告.md` 已存在 + 整体结论 = ❌ 打回
- 报告 § 必须修改的问题（P1 阻塞）至少 1 条
- 过去未跑过 `/iterate-A2`，或上次跑完仍未通过且累计轮次 < 2

如不满足，**立即停手**告知用户。

## 第 0 步：定位工作目录

```bash
DRAFT="${ARGUMENTS:-$(cat /tmp/new-feature-current.txt 2>/dev/null)}"
[ -z "$DRAFT" ] && echo "❌ 未指定短名，且 /tmp/new-feature-current.txt 为空" && exit 1
DRAFT_DIR="product-docs/_drafts/$DRAFT"
[ -d "$DRAFT_DIR" ] || { echo "❌ 工作目录不存在: $DRAFT_DIR"; exit 1; }
```

## 第 1 步：读 A2 报告 + P1 分诊（**本命令与 iterate-A7 的关键差异**）

```bash
A2_REPORT="$DRAFT_DIR/02-A2-审核报告.md"
grep -A 50 "## 打回时必填\|必须修改的问题" "$A2_REPORT" | head -80
```

把每条 P1 按报告里的分诊标注分两类：

| 类别 | 判定 | 处置 |
|---|---|---|
| **【形式类·可自动修】** | 路径不存在 / 段落漏填 / 5 态缺一 / 字段属性缺 / 内部自相矛盾——修复动作明确、不需要 PM 表态 | **可进闭环** |
| **【决策类·需 PM 拍板】** | 可用性取舍 / 需求理解分歧 / PM 假设冲突（P017）/ 任何"二选一"——AI 替 PM 拍板 = 空转风险 | **不进闭环 · 立即升 PM** |

> A2 报告未标注分诊时，由主对话按上表判定补标；拿不准 = 决策类（宁升勿自转）。

把分诊结果列给用户**一次**：

> "A2 打回了 N 项 P1：
>  - 形式类（K 项，可自动闭环修）：1. <...> 2. <...>
>  - 决策类（M 项，需要你先拍板）：1. <...>（选项 A/B 各带业务后果）
>
> 决策类请先逐条拍板；拍板结果会连同形式类一起交给 A1 修。
> 最多 2 轮闭环；2 轮后仍不通过我会停下让你介入。
>
> 是否开始？（决策类拍板完毕后）回复 `开干` 进入第 1 轮。"

等用户回复 `开干` 才进入第 2 步。**决策类未拍板完毕严禁开干**。

## 第 2 步：闭环循环（最多 2 轮）

记录轮次 `N = 1, 2`。每轮做以下 3 件事：

### 2.1 调 A1 按 A2 报告修

```
Task(subagent_type="product-expert", prompt="
工作目录：product-docs/_drafts/<短名>/
当前是【A2 闭环第 N 轮】（最多 2 轮）。

A2 已打回，必改 P1 项见 02-A2-审核报告.md § 必须修改的问题；PM 对决策类的拍板结果：<逐条附上>。请：
1. 严格按每条 P1 + PM 拍板结果修改 01-需求细化.md
2. 不要扩需求范围（仅修复问题项；新增需求内容需走原 /new-feature 第 1 步重做）
3. 修完重跑 pm-prd-writer 14 项自检 + Loop-1 启发式自走查（§ 6.5）
4. 第 1 句话格式：[A1 闭环修复 第 N 轮] 修复了 K 项 P1，14 项自检 = ✅/❌，Loop-1 = 通过/残留 M 项
")
```

### 2.2 主对话拿到 A1 返回 → 调 A2 重审

```
Task(subagent_type="requirement-reviewer", prompt="
审核对象：product-docs/_drafts/<短名>/01-需求细化.md
当前是【A2 闭环第 N 轮重审】。

请按 10 项硬性清单 + 第 11 项可用性快扫（软闸）重审，对比上轮报告确认 P1 项已修复。
覆盖原 02-A2-审核报告.md，结尾追加 § 闭环第 N 轮 复核结果。
第 1 句话格式：[A2 第 N 轮复核] 整体结论 = 通过/打回，本轮新增问题 = M 个，第 11 项快扫 = <0 警告/N 条警告>。
")
```

### 2.3 判断退出条件

| A2 第 N 轮结论 | 处置 |
|---|---|
| ✅ 通过（0 警告） | **退出循环**，告知用户："A2 第 N 轮通过 ✅，进 /new-feature 第 3 步 A3"，结束 |
| ✅ 通过（⚠️ 附可用性警告） | **退出循环**，但必须先按 /new-feature 第 2 步软闸流程把警告逐条亮给 PM 处置完，再进 A3 |
| ❌ 打回（同样问题） | 计数 +1；N < 2 → 进第 N+1 轮；N == 2 → 强制停下 |
| ❌ 打回（**新问题**） | 立即停下不进下一轮——新问题说明 A1 改坏了，必须 PM 介入 |
| ❌ 打回（含新增决策类项） | 立即停下升 PM 拍板（不消耗轮次，拍板后可继续） |

### 2.4 第 2 轮失败处置

如 N == 2 仍打回，停下告知用户：

> "❌ A2 闭环跑了 2 轮仍未通过：
>  - 第 1 轮 / 第 2 轮 各打回原因 = ...
>  - 累计未解决 P1：<列表>
>  - **建议处置**：
>    A. 你直接对 01-需求细化.md 给出逐条口述修改意见，我转 A1 定向改（推荐）
>    B. 回 /new-feature 第 1 步重跑 A1 多轮 Q&A（需求理解本身有分歧时）
>
> 我已停下不再自动 loop。"

## 第 3 步：成功收尾

A2 通过后：

```
✅ /iterate-A2 完成
- 工作目录：<DRAFT_DIR>
- 闭环轮数：N（≤ 2）
- 最终 A2 结论：通过（+ ⚠️ 警告处置记录，如有）
- 02-A2-审核报告.md 已更新（含 § 闭环第 N 轮 复核结果）

下一步：回 /new-feature 流水线第 3 步 A3 技术方案。
```

## 不允许的事

- ❌ 跑超过 2 轮（计数硬上限）
- ❌ 决策类问题进闭环让 AI 自转拍板（必须先升 PM）
- ❌ 跳过用户在第 1 步的"开干"确认
- ❌ 让 A1 在闭环里扩需求范围（仅修问题项）
- ❌ A2 重审通过但带 ⚠️ 警告时直接进 A3 不亮给 PM（软闸升 PM 是 patch-009 强制项）
- ❌ 同时 loop 多个 _drafts（一次只跑一个）

## 与 /iterate-A7 的关系

同一族 loop 工程（事件驱动 + 硬上限 + 新问题即停 + 升 PM 兜底），差异两点：① 上限 2 轮（A1 重写成本高）；② 多一道**问题分诊**（A2 打回常含产品决策类问题，AI 不替 PM 拍板——iterate-A7 面对的用例字段问题几乎全是形式类，无需分诊）。
