## 工作流程

### 1. 触及端识别（第一步）

基于需求关键词列出本需求会触及的端。常见模式：

- 后端接口新增 / 改动 → 后端 + 至少一个前端
- 跨端展示 → 多个前端 + shared 类型可能复用 / 新增
- 单端 UI 优化 → 单一前端
- 全链路新功能 → 后端 + 前端 + 可能 shared 新增类型

### 2. 现状梳理

对每个触及端，分别梳理：
- 涉及页面 / 路由 / 组件
- 现有相关接口
- 现有相关组件 / hooks / stores
- 与已知 DIFF / CHG 的关系

#### 2.x · P010 LOCKED · 硬编码 fallback 数据源 grep 自检（**必跑 · 缺即重做**）

### 3. 缺口识别

列出用户一句话需求里**没说但必须明确**的点（至少覆盖以下 7 类）：
- 用户角色（哪些角色 / 端使用）
- 触发入口（路由 / 按钮 / 菜单）

- 边界态（loading / empty / error / success / 权限）
- 跨端一致性（如多端展示，字段口径是否一致）
- 与现有功能的关系（替换 / 扩展 / 不冲突）

### 3.5 最佳实践推荐（**主动给方案，PM 描述简单时尤其重要**）

> ⚠️ 用户描述越简单 / 越含糊 → 你必须越主动给推荐，不要被动等用户写满。

每个需求至少给出 **3 类推荐**，每条推荐必带"推荐方案 + 来源依据 + A/B/C 候选"：

| 推荐类别 | 你必须做什么 |
|---|---|
| **项目内类比** | grep 项目内是否有类似交互模式（如折叠 / 跳转 / 聚合 / 视觉态切换）；如有，把它作为"推荐方案 A"，附行号引用 |
| **行业最佳实践** | 给"行业管理后台 / Dashboard / 表格 / 表单 / 弹窗"的标杆做法 2~3 选项，让 PM 选 A/B/C |
| **PM 没说但通常要拍的项** | 5 态文案 / loading 风格（skeleton vs spinner）/ error 是否带重试 / 空数据是否带引导 / 是否暗色 / 是否响应式 — 列出**默认值**让 PM"是否同意" |

**示例**（针对"加一个统计卡片"这类一句话需求）：

```
【最佳实践推荐 1】统计卡片视觉风格
- 项目内类比：<项目原生组件库>（如有 StatCard / 卡片组件）→ 强烈推荐复用，附行号引用
- 行业候选：A. 单值大数字 + 趋势箭头（GitHub）/ B. 数字 + 迷你图（Stripe）/ C. 数字 + 进度条（Linear）

【最佳实践推荐 2】数据加载态
- 默认建议：loading = 卡片 skeleton 行（参考 shadcn）/ empty = "暂无数据" + 图标 / error = 红色文案 + 重试按钮
- 是否同意？

【最佳实践推荐 3】响应式 / 暗色模式
- 默认建议：管理后台端固定宽，不做响应式；暗色按端区分（如有大屏类端才需暗色）

```
