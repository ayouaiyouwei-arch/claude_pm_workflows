# Skill · periodic-review

> 一句话定位：周期性扫描差异台账、变更登记、基线版本，输出复盘报告与下一周期建议（含基线升版建议）。

## 触发条件

- 每月 1 号（月度复盘）
- 每季度首月 1 号（季度复盘）
- 用户明确要求「做一次复盘」「做月度盘点」
- 一组差异条目的「等待裁决」时长超过 SLA
- 客户阶段验收前

## 输入

| 输入 | 是否必填 | 示例 |
|---|---|---|
| 复盘类型 | ✅ | 月度 / 季度 / 临时 |
| 时间窗 | ✅ | 2026-04-01 ~ 2026-04-30 |
| 当前生效基线 | ✅ | B1.0.x |

## 步骤

1. **读 `baseline/01-基线版本登记表.md`**：列出本周期内发布的所有基线版本
2. **遍历 `baseline/02-PRD-实现差异台账.md`**：
   - 统计各状态条目数（待裁决 / 修复中 / 已关闭 / 已废止 / 已废止-跟随版本 / 不通过-退回修复）
   - 标记「等待裁决 > 3 工作日」的条目（需立即升级）
   - 标记「修复中 > 5 工作日」的条目（需介入）
   - 标记「已废止-跟随版本」对应的版本是否已发布
3. **遍历 `baseline/03-产品变更登记.md`**：
   - 统计各状态条目数（申请中 / 评审中 / 通过 / 驳回 / 暂缓 / 转差异）
   - 标记「申请中 > 2 工作日」的条目
4. **联动 `08-PRD歧义与待澄清问题.md`**：检查超期未答复的歧义
5. **判断是否升基线**：
   - 若「已关闭」差异条目 ≥ 5 条且累计影响 P0 / P1 → 建议发布 patch（B1.0.x → B1.0.(x+1)）
   - 若「通过」变更申请 ≥ 3 条且新增模块 / 页面 → 建议发布 minor（B1.x.x → B1.(x+1).0）
   - 若 PRD 主版本切换 / 业务边界扩展 / 不兼容字段重构 → 建议发布 major（B1.x.x → B2.0.0）
6. **生成复盘报告**：见输出
7. **更新 `说明文档.md`**：第三节进度记录追加「YYYY-MM 复盘完成」
8. **触发下一步**：如建议升基线，调用 `publish-baseline` 技能；如有过期待裁决，升级提醒决策人

## 输出

```md
## 周期性复盘报告
- 复盘类型：月度 / 季度
- 时间窗：YYYY-MM-DD ~ YYYY-MM-DD
- 当前生效基线：B1.0.x

### 一、基线发布回顾
- 本周期发布版本：B1.0.x → B1.0.y
- 关键内容：（差异关闭 / 变更落地 / 新增模块）

### 二、差异台账状态
- 待裁决：N 条（其中超期 N 条：DIFF-XXX...）
- 修复中：N 条（其中超期 N 条：DIFF-XXX...）
- 已关闭：N 条
- 已废止 / 跟随版本：N 条
- 不通过-退回修复：N 条

### 三、变更登记状态
- 申请中：N 条（其中超期 N 条：CHG-XXX...）
- 已通过：N 条
- 已发布：N 条

### 四、PRD 歧义状态
- 未答复：N 条（其中超期 N 条）

### 五、升级建议
- 建议下一基线版本：B1.0.(x+1) / B1.(x+1).0 / B(x+1).0.0
- 触发条件：（说明）
- 拟纳入：DIFF-XXX, CHG-XXX

### 六、风险与升级提醒
- 决策人需介入：（人 + 待裁决项编号）
- 阻塞项：（如有）

### 七、下一步动作
1. （明确谁、何时、做什么）
```

## 禁止事项

- ❌ 不读基线版本登记表就出复盘
- ❌ 把超期项默默关闭而不升级提醒
- ❌ 跳过升基线建议（即使无升级需求，也要明确「本周期无升级」）
- ❌ 不更新「说明文档.md」进度记录
- ❌ 把复盘结论藏在群聊里不入文档
